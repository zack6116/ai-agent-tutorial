# Agent 的九种设计模式

进阶案例拆解 · 从 ReAct 的生活例子开始

## 1. ReAct 模式

参考图从 2022 年 10 月发表的 ReAct 论文讲起。ReAct 将推理与行动交替组织：行动获取外部观察，观察改变后续决策。[论文原文](https://arxiv.org/abs/2210.03629)

### ReAct 原理

![Agent 的九种设计模式：流程与结构图 1](/agent-diagrams/08-patterns-1.png)

::: info 举个例子：让孩子去厨房拿一瓶胡椒粉
一步步来：先看看台面上有没有；再拉开灶台底下抽屉看看；再打开油烟机左边吊柜看看。
:::

::: info 固定步骤与根据观察改变行动
**没有 ReAct 的固定脚本：** 不管第几步找到胡椒粉，都把几个地方看一遍。

**有 ReAct 的情况：** Action 1：查看台面。Observation 1：台面没有胡椒粉。Action 2：打开抽屉。Observation 2：抽屉里有胡椒粉。Action 3：把胡椒粉拿出来，任务结束。
:::

关键是每次行动后使用反馈，而不是盲目走完最初的计划。这种循环需要保留当前任务的观察结果；短期状态帮助它记住哪里找过、是否已经完成。

### ReAct 实现：通过代码理解原理

```python
# 教学演示：模拟环境反馈，不调用模型。
places = {"台面": [], "抽屉": ["胡椒粉"], "吊柜": ["盐"]}
observations = []
for place in ["台面", "抽屉", "吊柜"]:
    found = "胡椒粉" in places[place]
    observations.append({"action": place, "found": found})
    if found:
        print("找到胡椒粉，结束任务")
        break
assert len(observations) == 2
```

## 2. 工具使用：把答案连接到真实系统

**原理：** 模型选择工具并生成参数，程序执行，结果回传。** 例子：** 查订单时调用订单 API，而不是凭常识回答。** 实现：** 定义工具 schema、参数验证和统一错误返回。** 代价：** 依赖外部接口，必须处理超时与权限。

## 3. 规划与执行：先拆任务，再推进

**原理：** 把大目标拆成带依赖的步骤。** 例子：** 调研报告先定维度、再搜资料、最后比较。** 实现：** 保存任务清单和每步产物，必要时重新规划。** 代价：** 错误计划可能把后续工作带偏，因此计划要能被检验和修订。

## 4. 反思与修订：让反馈改变下一稿

**原理：** 产出草稿后，根据明确标准检查，再做有界修订。** 例子：** 核对报告是否每个数字都有出处。** 实现：** 检查器输出问题位置、证据和修改要求。** 代价：** 增加调用次数；没有外部证据的自我评价仍可能出错。

## 5. 检索增强：先找到依据，再回答

**原理：** 从知识集合中召回与问题相关的材料，作为回答依据。** 例子：** 查企业售后政策。** 实现：** 分块、检索、重排、引用与无答案处理。** 代价：** 检索到相关文本不代表它最新、正确或可供当前用户访问。

## 6. 路由：不同任务走不同路径

**原理：** 识别输入类型后，选择专门的处理流程。** 例子：** 售前问题走产品知识库，订单问题走查询工具，投诉转人工。** 实现：** 设置类型、置信条件和默认分支。** 代价：** 路由错误会让后面的正确工具也答错问题。

## 7. 并行：独立子任务同时处理

**原理：** 同时完成互不依赖的工作，再合并结果。** 例子：** 对一篇文章分别提取摘要、词汇和理解题。** 实现：** 统一输入与结果结构，处理某一分支失败。** 代价：** 总用量可能增加；有依赖的任务不能强行并行。

## 8. 多智能体协作：明确分工和交接

**原理：** 多个角色分别承担研究、写作、检查等职责。** 例子：** 研究员交证据，写作者交草稿，检查员核引用。** 实现：** 定义每次交接的字段、负责人和终止条件。** 代价：** 角色越多，通信和协调成本越高。

## 9. 记忆增强：跨步骤保留有用信息

**原理：** 将已确认的事实和状态保存，下一步按需读取。** 例子：** 客服记住当前订单号。** 实现：** 区分临时状态与长期资料，设置更新和过期规则。** 代价：** 错误信息持久化会持续影响后续任务。

::: warning 九种模式的补写范围
参考图只展示第 1 种 ReAct 的开头，没有显示其余八种名称。第 2—9 节为同风格教学补全，并不声称是原作者未展示的目录。它们可以组合，不是互斥的行业统一分类。
:::

## 选型：从最小的模式组合开始

| 任务 | 起步组合 | 何时增加复杂度 |
| --- | --- | --- |
| 查询订单 | 工具使用＋状态 | 需要连续查询时再加 ReAct |
| 企业知识问答 | 检索增强 | 问题类型明显不同时加路由 |
| 比较研究 | 规划＋检索＋检查 | 独立资料收集成为瓶颈时再并行 |
| 客服处理 | 路由＋工具＋记忆 | 多角色责任明确时再协作 |
