## 解决方案

::: info 引入RAG（Retrieval-augmented Generation，检索增强生成）技术
**RAG检索增强生成：** 当大模型需要生成文本或者回答问题时，用户首先通过检索预先维护的私域数据文档集合获得指导信息，然后把信息提供给 AI Agent。基于这些信息生成回答，使答案受检索证据约束，减少无依据内容。

**自定义召回阈值：** 按业务场景调整召回条件。阈值过高可能漏掉相关内容，过低可能引入噪声；需要用标注问题集比较结果，而不是把阈值当成“幻觉开关”。
:::

## 个性化引导完成特定任务

不同场景下，客服的问询顺序及信息收集可能存在差异，例如退换货场景，大致可分为：

::: tip 退换货任务链路
初步沟通核实原因 → 评估商品状况 → 判断是否符合条件 → 决策处理方案。
:::

每个环节中用户回答不同，相应处理也不同。用状态记录已收集的信息，用政策检索提供条件依据，用业务工具核对订单，用明确分支决定继续追问还是转人工。

## 2. 建立可复算的指标

人工介入率 = 转人工的有效会话数 ÷ 有效会话总数。比较前后必须使用同样的会话口径和时间范围，同时检查问题解决率和用户投诉。介入减少但问题没解决，不算有效改进。

| 指标 | 记录内容 |
| --- | --- |
| 转人工 | 触发原因、所处节点、是否真正接管 |
| 知识检索 | 有无结果、引用正确性、政策版本 |
| 任务完成 | 是否解决用户原问题 |
| 回复效率 | 首次响应、总处理时间 |
| 失败复盘 | 问题样本、根因、修改与复测结果 |

## 3. 补写实践：调节召回阈值

准备有答案、无答案、近似但不同规则的三组问题。固定其他参数，只改变一个召回阈值，记录命中、误召回、遗漏和最终引用是否正确。选择能达到业务验收要求的配置，并保存测试集版本。
