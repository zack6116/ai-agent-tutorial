### 前端与业务交互拆解

在参考图的 Coze IDE 中，前端界面通过事件、绑定和业务逻辑进行交互。案例中的绑定：工作流的输入绑定前端界面的元素 A，当用户在元素 A 输入内容后，工作流运行时会读取绑定元素 A 的内容，并传递至工作流内的大模型。

![Coze应用实战指南：流程与结构图 2](/agent-diagrams/05-coze-app-2.png)

### 实战：把外文精读工作流变成应用

页面包含一个文章输入框、一个阅读水平选择器、一个“开始精读”按钮，以及结果区域。先在工作流里跑通固定输入，再接页面变量。

| 页面元素 | 绑定对象 | 预期行为 |
| --- | --- | --- |
| 文章输入框 | article | 每次提交读取当前文本 |
| 水平选择器 | level | 默认值和用户选择都能传递 |
| 开始精读按钮 | 工作流运行事件 | 运行中显示状态并防重复点击 |
| 摘要区 | 输出 summary | 成功时显示本次结果 |
| 词汇列表 | 输出 vocabulary | 一条词语对应一张卡片 |
| 错误提示 | 本次运行错误 | 显示可理解原因，保留输入 |

## 三、数据库、知识库、插件和变量如何分工？

**数据库** 保存有固定字段的业务记录，例如每次阅读任务的编号和状态。** 知识库** 提供可检索资料，例如术语解释。** 插件** 执行外部能力，例如读取网页。** 变量** 负责一次运行或会话中传递数据。

不要为了用齐功能，把用户原文既放数据库又放知识库。先决定是否需要历史记录，再确定保存哪些内容和保留多久。

## 四、按用户路径测试

1. 输入文章，选择水平，点击按钮；检查工作流实际收到的值。
2. 等待运行；确认页面说明正在处理，而不是显示上一次的结果。
3. 成功后检查摘要、词汇、问题都对应本次文章。
4. 模拟失败；确认错误区可见、按钮恢复、文章还在。
5. 连续提交两篇文章；确认旧请求不会覆盖新结果。

::: tip 完成标准
页面中的输入、事件、输出能形成一条完整链路。发布前用一个没有编辑权限的测试账号体验页面，检查访问和数据范围。
:::

平台功能与界面以当前工作空间为准。官方参考：[工作流与对话流](https://docs.coze.cn/guides_workflow_and_chatflow)。
