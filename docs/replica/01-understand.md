## 一、AI Agent 的本质——从「听话」到「主动」

### 1.1 AI Agent 和普通 AI 的区别

**简单来说：**

- **普通 AI：** 像个听话的工具，你说「跳」，它就跳一下。
- **AI Agent：** 像个有主动性的助手，你给个目标，它自己规划怎么跳、跳多高。

用课程里的比喻，普通 AI 是「一个口令一个动作」，而 **AI Agent 是「人类只给目标，AI 自己找路」**。这里的主动性发生在程序允许的工具、时间和权限边界内。

::: warning 以一个「研究任务」为例，展示 AI Agent 如何工作
目标：比较三个适合团队使用的知识库方案，给出有依据的建议。你给出预算和使用条件，Agent 负责拆任务、查资料、检查信息是否充分、整理结果。
:::

### 1.2 把一次研究任务拆开看

| 步骤 | Agent 做什么 | 你应该能检查什么 |
| --- | --- | --- |
| 理解目标 | 确认人数、预算、部署限制 | 缺失条件被提问，而不是猜测 |
| 制定计划 | 列出价格、权限、检索、迁移四个维度 | 比较标准在查资料之前确定 |
| 使用工具 | 搜索官方文档和价格页 | 每个结论附来源与日期 |
| 检查结果 | 发现某产品价格缺失，继续查证 | 没有证据的格子明确标注 |
| 输出建议 | 汇总比较表和推荐理由 | 建议满足最初的限制 |

## 二、智能体由什么组成？

模型负责理解和决策；工具负责查询和执行；记忆保存任务上下文；编排程序负责连接这些部分。系统提示词告诉模型角色、目标、可用工具和完成标准。

::: tip 用一个客服场景记住四个部分
“查一下我的订单”：模型识别查单需求 → 记忆提供当前会话中的订单号 → 工具查询订单 → 编排程序检查返回值 → 模型组织回答。模型生成了工具参数，不代表工具已经成功执行。
:::

## 三、什么场景适合用 Agent？

先检查任务是不是需要根据中间结果改变下一步。固定格式提取可以用一次模型调用；稳定审批流程适合工作流；需要多轮查询、补充信息和调整方案的任务才更需要 Agent。

| 场景 | 起步方式 | 原因 |
| --- | --- | --- |
| 把会议记录整理成三条待办 | 单次模型调用 | 输入和输出明确 |
| 收到表单后检查字段并归档 | 固定工作流 | 路径可提前定义 |
| 查找某个系统故障的原因 | 带工具的 Agent | 下一次检查取决于上次结果 |
| 自动审批退款 | 工作流加人工审批 | 关键动作需要业务规则和责任边界 |

## 四、从一句目标到第一张任务卡

```text
目标：为客服整理订单异常处理建议
输入：订单号、用户问题
工具：查订单、查物流、检索售后政策
输出：已确认的事实、政策依据、建议动作
停止条件：结论有依据；或三次查询后仍缺资料
人工接管：退款、改地址、取消订单等写操作
```

**练习：** 用自己的业务填写这张卡，再准备三条输入：正常问题、信息不足的问题、工具不可用的问题。能说清三条输入各自如何结束，才算理解了这个 Agent。
