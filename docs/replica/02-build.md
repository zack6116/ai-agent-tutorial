# 从0-1打造商用 AI Agent（智能体）

从案例入门 · 模型、工具、提示词与业务闭环

## 一、什么是智能体？

智能体是一种能够感知其所处环境、做出决策并采取行动以实现特定目标的自主实体。智能体的复杂程度各不相同，从简单的对刺激做出反应的反应式智能体，到能够随着时间推移进行学习和适应的更高级的智能体。

**常见的智能体类型包括：**

> - **反应式智能体：** 直接对环境变化做出反应，没有内部记忆。
> - **基于模型的智能体：** 利用对世界的内部模型来做出决策。
> - **基于目标的智能体：** 根据要实现的特定目标来规划行动。
> - **基于效用的智能体：** 基于效用函数评估潜在行动，以实现结果的最大化。

聊天机器人、推荐系统和自动驾驶汽车都可以包含智能体式组件。它们不一定都使用大语言模型，本页聚焦基于 LLM 的应用。

**我们构建的智能体核心组件包括：**

> - **模型：** 智能体的“大脑”，负责处理输入并生成响应。
> - **工具：** 根据用户请求，智能体可以执行的预定义函数。
> - **工具箱：** 智能体可使用的工具集合。
> - **系统提示：** 指导智能体如何处理用户输入并选择正确工具的指令集。

### 2.1 准备工作

参考图提到一个名为“Build an Agent from Scratch”的仓库，但没有给出地址。本页补写一个不依赖特定仓库的订单助手练习。

**1. Python 环境设置**

- 安装 Python：从 [Python 官网](https://www.python.org/downloads/)获取当前受支持版本；原图“3.8 及以上”属于当时的环境说明。
- 验证安装：在命令行输入 `python3 --version`。
- 创建虚拟环境：在项目目录运行以下命令。

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
```

Windows 的激活命令为 `.venv\Scripts\activate`。后续选择模型 SDK 时，以该 SDK 声明的 Python 版本范围为准。

### 2.2 先定义业务输入和验收结果

这次只完成“查询订单状态”。输入订单号，输出订单状态；订单不存在时明确告知，缺少订单号时追问。先不处理退款、取消和改地址。

```json
{"order_id":"DEMO-001","question":"我的订单发货了吗？"}
```

### 2.3 把业务能力封装成工具

```python
ORDERS = {"DEMO-001": {"status": "已发货", "carrier": "示例物流"}}

def query_order(order_id: str) -> dict:
    if not order_id:
        return {"ok": False, "error": "missing_order_id"}
    order = ORDERS.get(order_id)
    if order is None:
        return {"ok": False, "error": "order_not_found"}
    return {"ok": True, "order": order}

assert query_order("DEMO-001")["ok"] is True
assert query_order("unknown")["error"] == "order_not_found"
```

这是本地教学数据。接入真实订单系统时，由后端根据登录身份检查订单归属，不能只信任模型传入的订单号。

### 2.4 系统提示词与工具执行

::: tip 可直接改写的系统提示
你是订单查询助手。查询事实必须来自 query_order 的返回值。缺少订单号时先追问；订单不存在时说明无法找到；工具出错时说明当前无法查询。不要自行补造物流状态。只回答订单问题，不执行退款或取消。
:::

模型输出工具名称和参数后，宿主程序负责验证参数、执行工具，并将结果带回会话。把工具结果当作数据，不把其中任意文本提升为系统指令。

### 2.5 数据库、UI 和部署

| 环节 | 最小实现 | 验证方法 |
| --- | --- | --- |
| 数据库 | 按用户和订单号查询状态 | 用户只能查自己的订单 |
| UI | 输入框、提交按钮、状态区、结果区 | 点击后有加载状态，失败可重试 |
| 测试 | 正常、缺字段、不存在、超时四类 | 每类结果与任务卡一致 |
| 部署 | 服务端保存密钥，记录请求编号 | 前端源码不包含密钥 |

## 三、从能运行到能交付

保存每次任务的输入摘要、工具调用结果、耗时与结束原因。上线前先用测试订单验证，再让业务同学检查答复。交付物应包括操作说明、接口契约、测试记录和人工接管方式。

**完成检查：** 输入 DEMO-001 得到示例状态；输入 unknown 得到不存在；输入空值触发追问；模拟超时后页面仍能恢复。接入真实模型和业务接口后的效果，需要用真实调用另行验收。
